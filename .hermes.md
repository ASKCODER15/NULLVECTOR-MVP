## Product vision
NullVector is a developer-first security platform for modern web applications and AI-built applications. Its goal is to make useful, understandable defensive security testing accessible to teams and builders who may not have specialist security expertise.

## Core problem
AI coding and app-building tools make software creation much faster and let non-security specialists build applications. Security testing, however, remains difficult and fragmented. NullVector aims to connect safe testing with clear evidence, severity, remediation guidance, and retesting in one practical workflow.

## Core product flow
User → Application URL → Authorization confirmation → Target validation → Fingerprinting → Scan planning → Safe security tests → Evidence → Severity + Confidence → Finding → Remediation → Retest

## Finding structure
Findings should use a normalized structure such as:

```json
{
  "test_id": "...",
  "category": "...",
  "status": "...",
  "severity": "...",
  "confidence": "...",
  "summary": "...",
  "evidence": "...",
  "impact": "...",
  "recommendation": "...",
  "timestamp": "..."
}
```

**Severity is not confidence.** Severity describes the potential impact if the issue is real. Confidence describes how strongly the test evidence supports the finding. A potentially critical issue can have low confidence, and a low-severity issue can be confirmed with high confidence. Keep these assessments distinct in findings and reports.

## Security boundaries
NullVector performs authorized defensive testing only. Obtain and respect authorization before scanning; validate targets and constrain every request. The scanner must protect against:
- localhost
- private IPs
- link-local IPs
- cloud metadata endpoints
- unsafe redirects
- SSRF
- destructive actions
- arbitrary command execution
- excessive requests

Use controlled targets, fake secrets, canaries, mock tools, and authorized test accounts. Apply request timeouts and response-size limits. Revalidate destinations after redirects and prevent requests from escaping the authorized target scope.

## Development-agent separation
Codex, OpenCode, and Hermes are development agents only. They are not part of the NullVector runtime. NullVector's runtime AI is separate from these development agents.

## Current MVP priority
Prioritize a reliable core scanner:

URL → Authorization → Safe web scan → AI endpoint detection → Prompt Injection testing → System Prompt Leakage testing → Sensitive-output/canary testing → Evidence → Remediation → Retest

Do not prioritize enterprise features ahead of making the core scanner reliable.
